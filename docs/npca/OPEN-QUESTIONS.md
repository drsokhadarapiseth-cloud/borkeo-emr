# NPCA v1.4 questions requiring NPCA confirmation

Do not enable production submission until NPCA approves the test payloads.

1. Endpoints: this supplied Postman collection actually uses GET `/api/v1/external/beneficiary/search`, POST `/api/v1/external/visits`, GET `/api/v1/external/visits/processed`, and POST `/oauth/token`. The PDF submission path is `/api/external/v1/visits`; another documented beneficiary path is POST `/api/v1/beneficiaries/search`. All paths and methods are settings. No automatic fallback sends a payload to a different endpoint.
2. OAuth: Postman sends URL-encoded token grants; the update prompt specifies JSON headers on every call. This implementation sends JSON. Confirm the server accepts JSON password and refresh grants. The token request has no Bearer token until authentication succeeds.
3. `sample-json/visit_sample_data_form.json` is malformed near line 294. It is not parsed as an integration template.
4. Excel `API Objects` is authoritative: use flattened visit fields with `patient` and the plural component arrays, `request_code`, `diagnoses`, singular `referral`, trimmed `title`, `soaps`, `progress_notes`; no `class`/`class_name` field is added because neither is defined for the concrete Excel encounter models. Confirm these choices against the server validator.
5. Prescription medication identifier is `code` in the data-structure workbook, not `medicine_code`; invoice medications use `medicine_code`. CMS is emitted as `code` in prescriptions. The workbook has no separate medication `form` field. Confirm whether NPCA wants that extra field. Form/strength remain available in local review and the medicine catalogue.
6. Diagnosis uses `diagnosis_type_name` with `In`, `Out`, `Primary`, etc. The Standard Lookup also provides DIAGT codes. This field is explicitly a name, so names from the Diagnosis Types sheet are sent. `diagnosis_name` is incorrectly typed datetime in Excel; it is handled as string. Confirm both corrections.
7. Referral health-facility `name` and `code` descriptions are interchanged in one table. Send the name as name, the official code as code; require both. Do not invent CPA3 facility codes or public referral document URLs. No clinical attachment is exposed publicly just to satisfy this field.
8. Child 1 month–5 years uses `ENTY-00000A9M` from Excel, which differs from the PDF. Excel sheet title says 1Y–5Y, while the form itself says 1M–5Y. Forms are gated by `NPCA_SEND_FORMS` (default true).
9. Beneficiary response does not fully specify eligibility flags, card validity periods, or household response wrappers. The initial adapter accepts `data` arrays or `data.beneficiaries`/`beneficiaries`, explicit `dead:false`, explicit `eligible:true` or `eligibility:true/eligible`, and a SPID. Missing eligibility blocks claims. Confirm the live response before enabling. Multiple distinct benefit schemes block automatic selection; NPCA must confirm how the clerk chooses the applicable scheme.
10. Payment mapping: HEF_POOR/HEF_EQUITY → PATY-0000N09; HEF_VULNERABLE/HEF_VULNERABLE_FAMILY → PATY-00003LD; NSSF_WORKER → PATY-0000G3E; NSSF_CIVIL → PATY-00B003F; generic NSSF → PATY-000K010; CASH → PATY-00T001A; DISCOUNT → PATY-0000H08; EXEMPT/FULL_WAIVER → PATY-0J0000C. Generic INSURANCE, NGO, PAID, NSSF_OUTSIDE, and unspecified DIRECT are not inferred. They require an administrator-reviewed mapping to an existing official code. Patient benefit cards determine the verified claim scheme, not a guessed default.
11. No NPCA service-code catalogue is included in these workbooks. Borkeo service codes (OPD_CONSULT, ward charges, lab and imaging charges, etc.) are not automatically NPCA service codes. Administrators must record NPCA-confirmed service mappings; unmapped billed services block submission. Currency/rate and discount semantics must also be confirmed, particularly mixed-currency invoices.
12. Nationality/ethnicity: use only the provided Nationalities codes, including KHM. Borkeo values outside that list block. Free-text route/method and encounter ward/service names are retained because those fields have no code list in Excel.
13. The Medical Histories list has nine sections, and physical examination has eleven. The clinical form includes `Abdomen` and `Past Surgery History`, whereas reference names are `Gastro-Intestinal System` and `Past Surgical History`. Do not silently invent additional sections. Official spelling `Central Nervouse System` is preserved.
14. The Form Structure refers to `Birht Control Type` (typo), `Positivity`, and `Presentations`; the supplied value sets need careful confirmation before converting any free-text or boolean field. Unknown values block, rather than defaulting to normal/negative. No required clinical measurement, provider, diagnosis, or dispense quantity is invented.
15. Resubmission: the PDF describes restrictions but does not enumerate all lock/duplicate rules. Locally refuse Ready and Processing resubmission; allow corrections to Failed and updates to Pending only with a changed payload, retaining the same visit code. Reconcile ambiguous timeouts through the processed endpoint before retrying. Confirm external locking behavior and idempotency.
16. Processing query: PDF says `status`; Postman says `processing_status`. Single-visit polling uses `visit_code`, avoiding that conflict. Confirm whether a code-filtered request returns one object or a paginated list. Accept `visit_ulid` and the PDF's `uuld` typo only as response identifiers.
17. The PDF's HTTP-500 example contains body `http_code:403`. HTTP transport status controls retry; a business `success:false` response is never accepted as success.
18. Required fields not stored structurally by a given Borkeo form remain validation issues with correction links. A locally constructed payload is not evidence of NPCA certification. NPCA's test server must accept the actual OPD/IPD/transfer/referral/maternal/child examples before production.
19. Form Structure value-set labels differ from Form Values: `Birht Control Type` → `Birth Control Type`; `Presentations` → `Presentation`; `Delivery Types` → `Delivery Type`; `Contraceptive Method Type` → `Type Of Contraceptive Method Received`; singular Newborn/Child Examination Result → plural Results. These are name aliases only; OBVA codes still come from the workbook. `Positivity` is absent altogether and cannot be invented.
20. Patient `code` uses the stable Borkeo Health ID (patient key as fallback), as requested. The beneficiary's `patient_code` is stored locally but is not substituted for that identity without NPCA confirmation.
21. New daily-note authorship is captured additively on changed notes only. Older notes may lack reliable historical provider metadata. Latest saved triage can also be later than the initial consultation after an edit. Such cases block rather than assigning today's provider or inventing earlier measurements.

## Added in v48.0.0 (comparison with the v1.4 PDF)

22. Field names that differ between the PDF and the data-structure workbook are now sent under both names until NPCA confirms one: `diagnosis_type` (PDF 6.9.2) next to `diagnosis_type_name` (workbook), and `medicine_code` (PDF 6.11.3) next to `code` (workbook) in prescription medicines, which also carry `form` as in the PDF example. Confirm the name NPCA validates, and that the extra field is accepted.
23. The PDF base Encounter (5.1) requires `class` ("IPD", "OPD", "EMERGENCY"); the workbook encounter models do not define it, and the 5.1 example writes `class_name`. `class` is now sent on outpatients, inpatients and emergencies; surgeries take the class of the visit and progress notes "IPD". Confirm the name and the value for surgeries and progress notes.
24. The workbook requires `referral.referred_to.document_file` as a public HTTPS address of the referral letter; the PDF (6.12) does not list it. The EMR never makes a patient document public to fill it. Confirm whether it is required and how the letter should be provided.
25. `disabilities` (6.1.1, array of strings): Registration records only disabled / not disabled. A disabled patient is sent as one entry, the Khmer word for "disabled"; nothing is sent otherwise. Confirm whether NPCA has a list of disability values.
26. Processing endpoint date range (4.4): the EMR sends `discharged_at_from` / `discharged_at_to` (or the admitted pair) with `per_page=100` and `page`, and follows `last_page` from `data.last_page`, `meta.last_page` or `last_page` (at most 50 pages). Status may be a number or the 4.5.4 name. Confirm the paging parameters and the response shape.
27. CMS medicine codes: only single codes of two letters and 3 to 4 digits are accepted locally. Nine rows of the medicine catalogue have a note (`Core`, `Comp`, `WHO`, `Reserve 9th`, `A.lt of Clarif`) or two codes (`AA0410, AA0411` for Paracetamol 500 mg tablet) in the code column; a prescription of these medicines is blocked until the hospital enters the correct single CMS code. Confirm that NC009 / NJ060-style codes (3 digits) are valid CMS codes.
