Borkeo EMR v42.7.0 - Automatic patient ID card and QR preview
Previous version: 42.6.0

WHAT WAS WRONG
A new registration saved and redirected to the patient list before staff could preview the patient card. Card and QR generation required opening the card manually.

WHAT CHANGED
After a successful first registration save, the existing card preview opens automatically. The QR contains the Patient ID returned by the successful save. Printing remains manual. Closing the preview continues the original navigation. Failed saves, existing patient edits, returning visits, and clinical saves do not open it automatically. The existing manual card button remains available. Patient numbering and card layouts are preserved.

INSTALLATION FOR ANTIGRAVITY
1. Stop the EMR server and make a backup using the hospital's existing backup procedure.
2. Use the full unified diff below against version 42.6.0. Apply only the listed code files. Do not replace data/, patient databases, uploads, backups, .env, or .gitignore.
3. Start the EMR again using Start-Borkeo-WiFi.bat.
4. Refresh the browser. Save a synthetic new registration and confirm the card preview opens with its Patient ID QR. Print manually if needed, then close the preview to continue.

VALIDATION
Verified: npm test 948/948 pass; npm run check:khmer passes. Tested in a disposable copy with 30 synthetic patients. Combined unified diff reverse-check passes.
Run npm test and npm run check:khmer in a disposable copy with synthetic fixtures. Regression checks cover saved-ID QR generation, preview dismissal, redirect ordering, and successful/new registration gating. ANC changes are a separate update, pending behavior discussion.
