================================================================================
Borkeo EMR Update Note: Version 42.1.0
Superuser becomes a "switch user type" account - new Infectious diseases ward
================================================================================

Date: 2026-10-22
Previous Version: 42.0.0
New Version: 42.1.0
Patient data: not touched. No database table change.

--------------------------------------------------------------------------------
1. WHAT WAS WRONG
--------------------------------------------------------------------------------
a) The Superuser was not a real staff account. It had its own "SUPERUSER"
   role and many special permission bypasses (all menu buttons, an inbox
   with every team's messages, pages that changed its role by themselves).
   So what the Superuser saw and could do was different from what a real
   Registration, Triage, Doctor, Nurse, Lab, Pharmacy or Cashier account
   sees and can do. Testing with it did not show the real staff experience.

b) Opening a page switched the Superuser's role automatically (v42.0). The
   role could change without the user asking.

c) Triage offers "ផ្នែកជំងឺឆ្លង" (Infectious diseases), but the server did not
   know this ward. A patient sent there belonged to no ward: nobody saw the
   patient in Wards and beds, nobody could open the record, and the ward was
   missing from ward medicines and the daily report.

--------------------------------------------------------------------------------
2. WHAT CHANGED
--------------------------------------------------------------------------------
a) Superuser = exactly ONE real staff user type at a time.
   - The SUPERUSER role and the "all buttons" mode are removed. The account
     holds the 15 real roles and every ward, so it can become any user type.
   - While switched it behaves exactly like a real account of that type: the
     same side menu, pages, buttons, data, server refusals and message bell.
   - Every Superuser permission bypass was removed from the server and the
     page scripts. The account name is used only for the switch button and
     for the audit log.
   - The automatic role switch on page open (v42.0) is removed. The role
     changes only with the picker or the switch button.
   - An old session with the SUPERUSER role goes to the picker.

b) After login the Superuser always goes to the user type picker first
   (/context): choose the role, then the ward for roles that need one
   (Midwife = Obstetric only; Nurse = not Obstetric; Chief of ward and Ward
   head = not OPD; Doctor = any ward including OPD). All 15 user types are
   listed (the missing Vice director label was added).

c) Top bar button "ប្តូរប្រភេទអ្នកប្រើ" on every page, for the Superuser
   account only. It opens a small window with the same role and ward
   choices. After a switch the account goes to the landing page of that user
   type, the same as a real login (the server sends this page, so the picker
   and the window always agree). Real staff do not see the button; their own
   role switch in the user menu is unchanged.
   Every switch is written to the audit log: WORK_CONTEXT_CHANGED with
   { role, wardCode, switchedBy: 'Superuser' }.

d) Messages: the bell, the list and "complete" use the active user type and
   ward, the same as real staff. A task completed while switched to
   Laboratory is completed for the Laboratory team.

e) Signatures saved while switched show "Superuser · <Khmer role label>",
   for example the triage signature shows Superuser · ផ្នែកទ្រីយ៉ា.
   Real staff signatures are unchanged.

f) New ward "ផ្នែកជំងឺឆ្លង" (code infectious, inpatient):
   - known by the server, so ward doctors, nurses, chief of ward and ward
     head of this ward see and open its patients;
   - in ward medicines, the daily report, OPD -> IPD transfer, staff message
     destinations, finance departments and the ward name lists;
   - bed map: one room with four beds, the same layout as the TB ward. It is
     added to the saved bed map automatically when Wards and beds is opened.
     The room is named "ផ្នែកជំងឺឆ្លង" (it can be renamed with "កែបន្ទប់");
   - two staff accounts are created when the server starts, like every other
     ward: doctor_infectious and nurse_infectious (password 1234; please
     change it, or deactivate the accounts in Account management if they are
     not needed).

g) /context page: after choosing a role, every account now goes to the same
   landing page as after login (for example Vice director -> Billing,
   OPD nurse -> Paraclinic handoffs).

Checked in a test copy with synthetic patients only, in Microsoft Edge:
  Logged in as Superuser -> picker -> Registration. Then, using the top bar
  button for every step and clicking every side menu button at each step:
  register -> triage to OPD -> cashier -> OPD doctor -> lab -> cashier ->
  lab result -> OPD doctor prescription -> pharmacy dispensing; and
  register -> triage to Infectious diseases -> ward doctor (opens the record,
  admission medicines) -> ward nurse (sees the patient, bed 1) -> daily ward
  medicines (ward head, chief of ward) -> director approval.
  npm test: 903 of 903 pass. npm run check:khmer passes.

--------------------------------------------------------------------------------
4. INSTALLATION (one step at a time)
--------------------------------------------------------------------------------
The files are already updated in this folder. If you use this folder as is,
only steps 1 to 4 are needed.

Step 1: Close the EMR server window (or press Ctrl + C in it).
Step 2: Double-click "Start-Borkeo-WiFi.bat".
Step 3: In the browser press Ctrl + F5 once and log in as Superuser. The
        page "ជ្រើសរើសតួនាទី និងផ្នែកការងារ" opens. Choose a role (and a ward
        if asked) and press "ចូលប្រើ EMR".
Step 4: Press "ប្តូរប្រភេទអ្នកប្រើ" at the top of the page to change to
        another user type.

For Antigravity (only when applying to another copy of v42.0.0): apply the
code change in section 5 exactly (it keeps each file's line endings), then
run "npm test" and "npm run check:khmer".
